# Test plan

Two layers: automated suites that run on every push, and an in-game checklist for what only the game can
show (taint, the real gamepad, Blizzard's own windows).

## Automated

Run `tests/run.ps1` (Windows) or `tests/run.sh`. Each suite runs in its own process with LuaJIT, or with
Neovim's built-in LuaJIT (`nvim -l`). CI runs them before any release is packaged.

| Suite | Covers |
|---|---|
| `static` | TOC lists every Lua file, and every listed file exists; Lua 5.1 syntax; every secure snippet goes through `ns.Snippet` and passes Blizzard's snippet compiler and the restricted environment with its real signature; the load-time snippet check; the UI uses only the engine API. |
| `engine` | The secure engine end to end: tap / hold / long hold for every action kind, ranks, macros, toys, mounts, publishing, crossbar labels, Bind (controller and mouse), place mode in and out of combat, Totem Commands switch, the pre-0.10 macro cleanup, slash commands, reloads in combat. |
| `ui` | The setup window and picker against a fake engine, in both navigation modes: Blizzard's gamepad UI calls (and their silent refusals in combat), our own bindings and their combat handling, prompts and focus visuals, the bind banner, the minimap button, the addon compartment, the menu dial entry, and fields Blizzard reads without a taint barrier. |
| `nav` | Direction finding of our own controller navigation. |

Every suite also fails if the addon creates a global it shouldn't.

What the test world emulates, from Blizzard's source (`tests/lib`):
- The snippet compiler's refusals (`RestrictedExecution.lua`), the restricted environment's globals and
  frame-handle methods (generated by `tests/tools/gen_restricted_env.py`), the scrubbed `GetActionInfo`.
- State drivers resolving `[combat]` and converting numeric values to numbers (`SecureStateDriver.lua`).
- `SecureActionButton_OnClick`'s key-down / release rule, including mouse clicks acting on release.
- `HideUIPanel` refusing addon code in combat.
- Strict widgets: a method the mock doesn't have is nil, as it would be in game.

What it can't show: real taint propagation, how the game routes gamepad presses between crossbar pages,
Blizzard windows' own behaviour, timing of the secure tick in a real fight. That's the checklist below.

When adding a feature: add the test first in the suite that owns it, see it fail, then write the code. If
the feature needs a Blizzard function the test world doesn't have, the suite stops with "not emulated";
add it to `tests/lib` from Blizzard's source, not from memory.

## In game

Before each release, on a character with the addon freshly installed and one upgrading. Note the client
build. Anything marked **verify** has never been confirmed in game.

### Load

- [ ] `/reload`: no Lua error, no red "secure code ... contains" message, no "Blizzard blocked" message.
- [ ] `/gestures test`: lists the gestures, then "secure ticks: N in 2 s (working)".
- [ ] `/reload` during combat, then leave combat and hold a gesture: the hold arms. **verify**

### Gestures

For a Tap of each kind (spell, item, toy, mount, macro that casts a spell, macro that shows nothing):

- [ ] Tap: the slot's own action, on release.
- [ ] Hold: one rumble and "Release for ...", then the Hold action on release.
- [ ] Long hold: two rumbles, then the Long hold action.
- [ ] A ranked spell on the bar at another rank still triggers the gesture.
- [ ] A macro Tap: choosing it, binding it and using it work (this relies on `GetMacroIndexByName`). **verify**
- [ ] Hold a gesture, press and release another crossbar button, release the gesture: both act. **verify**
- [ ] Hold a gesture, switch bars (L1 / R1) or pages (both shoulders + D-pad left / right) before letting
      go: nothing casts, and the next press of that button works. **verify**
- [ ] In a busy fight (many targets, modifier presses), holds don't arm noticeably early. **verify**

### Bind

- [ ] Bind a gesture with Bind, and with a mouse drag from the list: those buttons show the gesture's icon and
      do its holds.
- [ ] Put the gesture's Tap spell on another button from the spellbook or the game's bind screen: that
      button shows the spell's own icon and casts on press, no hold.
- [ ] Move a bound button's action with the crossbar's edit mode: the gesture moves with it. **verify**
- [ ] Switch talent spec and back (if your character has two): bound gestures work again on return. **verify**
- [ ] Update from 1.0.x on a character with gestures set up: every button that held a Tap is still the
      gesture. **verify**

- [ ] Controller: Bind, press a button on another bar and on another page: the Tap goes there, "placed",
      nothing cast.
- [ ] Bind with the mouse: click a crossbar button: the Tap goes there and nothing is cast. **verify**
- [ ] Bind, enter combat, open `/gestures` (cancels), leave combat: the next press casts normally.
- [ ] Bind, let it time out (60 s): "bind cancelled".
- [ ] Mouse: drag a gesture from the list onto a slot.
- [ ] Name & icon: the crossbar button shows them; OK without changes keeps following the Tap's name.

### Window and controller

- [ ] Open from: the menu dial (release the stick on it; again to close), minimap button, addon
      compartment, key binding, Options > AddOns, `/gestures`.
- [ ] LT / RT switch between the window and bags; View toggles; A selects; B closes the picker, then the
      window. Prompts and the focus glow show.
- [ ] Enter combat with the window and the picker open: both close, no "Interface action failed" or
      "Blizzard blocked" message. **verify**
- [ ] Open the window in combat with the mouse: it's locked; its X closes it.
- [ ] Picker open, click another gesture in the list: the picker closes.
- [ ] Picker with the D-pad, in both navigation modes: left / right move along the tabs, a grid row, the
      pager and the bottom buttons, and never drop into the grid; up / down move between the name box, tabs,
      grid rows, pager and buttons from any column (including past empty grid rows). **verify**
- [ ] Ten gestures: New is off.

### Own navigation (`/gestures padnav own`)

- [ ] D-pad moves the highlight, A selects, X clears, B closes.
- [ ] Window open, enter combat: the D-pad and A / B / X work on the crossbar during the fight.
- [ ] Close the window during combat, leave combat: the D-pad and face buttons still work on the crossbar.
- [ ] `/gestures padnav blizzard` returns to the default.

### Upgrades

- [ ] From the previous release with gestures set up: they still work after updating.
- [ ] Totem Commands enabled: the window offers "Switch from Totem Commands"; switching sets up the totem
      gesture and turns Totem Commands off.
